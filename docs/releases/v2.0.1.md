# Retro Web UI v2.0.1 candidate

This is a release-engineering draft, not a published release. Existing tags
and releases remain unchanged.

The candidate is a backward-compatible distribution-hardening patch over the
public v2.0.0 desktop release. It does not add themes, framework support, or a
new semantic conversion engine.

## User-visible fixes

- Codex readiness is checked automatically on first launch with actionable,
  redacted missing-launcher and App Server diagnostics.
- App Server turns use a stable structured result schema. Missing runtime,
  browser, visual, accessibility, or target checks remain visible as review
  items and can no longer be hidden by a deterministic `Complete` result.
- Streaming token fragments no longer flood the event list; authoritative
  completed messages and bounded command/item history are shown instead.
- Frozen Core diagnostics distinguish a bundled Python runtime library from a
  runnable interpreter, and the conversion receives a precomputed canonical
  theme bundle without depending on a system Python installation.
- Every native archive contains an exact portable `INSTALL.md`.

## Distribution gates

- Windows and Linux now join macOS in re-extracting and executing the final
  archive rather than only exercising the pre-archive build tree.
- Archive paths, roots, launchers, Windows case collisions, links/special files,
  notices, version output, smoke JSON, and checksums are validated.
- macOS has a stable bundle identifier plus aligned short/build versions before
  final ad-hoc signing and strict post-extraction verification.
- Linux builds on Ubuntu 22.04, records GNU ABI requirements, and rejects a
  required GLIBC newer than 2.35.

See [desktop distribution and clean-install guide](../distribution.md) for the
verified support boundaries and uninstall/troubleshooting instructions. The
[distribution hardening validation report](../distribution-validation-report.md)
records the public-baseline replay, exact candidate artifacts, real installed
App Server conversion, independent browser verification, and release
recommendation. This draft does not create or authorize a release.
